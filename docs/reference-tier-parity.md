# Advisory reference tiers

The backend mirrors deployed core4 `9ef92a235`: bands version 3, the second-worst fold, and its optional per-variable `gross_max` guard. The older wording in #1169 and oracle-reference#9 describes v2 and an obsolete multiplier representation. The owner selected deployed v3 parity. Both JSON fixtures in `shared/fixtures/reference_*` are byte-identical to that core4 commit.

`ReferenceVerifierClient.scoreObservation` and `ReferenceShadowScorer.scoreReveal` accept optional `tieringContext: { height, grossGuardActivationHeight }`. Heights must be nonnegative JavaScript safe integers; larger u64 heights are rejected rather than rounded. A null activation height means unscheduled. The guard activates inclusively at `height >= grossGuardActivationHeight`. Omitted context explicitly selects pre-activation behavior. The production reveal path supplies its resolved core4 height and `REFERENCE_GROSS_GUARD_ACTIVATION_HEIGHT`. Operators must mirror the deployed chain schedule in that setting (including governed schedule changes); unset/empty explicitly means unscheduled. This is an operator-provided schedule, not automatic schedule discovery. Invalid configuration skips only advisory scoring after reveal finalization, never acceptance or rewards. Direct callers that omit context remain pre-activation. No wall-time activation is inferred.

The oracle request carries the same context as `tiering_context` with snake-case field names. The backend validates bands version 3 and recomputes the tier from residuals; it does not trust the oracle advisory tier. Client diagnostics expose `foldRule` and `grossGuardActive`. Non-finite residuals are outliers but do not trigger the finite-only gross guard. Unknown source/variable pairs are ignored. Exact good/marginal boundaries remain inclusive; the gross boundary is strictly greater-than. Full fold cases and pre/at/post-activation vectors cover the policy.

This is shadow/advisory scoring only: no reward writes, enforcement switches, confidence changes, or environment defaults change. The existing `reference_scores` table stores the bands version and residual array, with no free-form policy metadata column. Persisting activation context/fold diagnostics needs a separate schema follow-up; the residual array shape is preserved here. No live chain, oracle or testnet access is needed for these tests. Deploy the v3 oracle before enabling this backend client against it; a v1/v2 sidecar is rejected as a bands-version mismatch.
