# Ambient device admission

Pending providers have no device-verification path: a submitted MAC is rejected with 422 `MAC_PROVIDER_UNVERIFIED`. Historical pending-provider rows do not reserve the Ambient MAC namespace, and switching such a retained MAC to Ambient requires account verification. Legacy rows without a provider tag retain the historical Ambient default.

Self-service registration normalizes submitted MAC case and surrounding whitespace, then requires the MAC to occur in the supplied Ambient account device list. A supplied Ambient MAC without a validating key, or a different device, receives 422 `AMBIENT_MAC_NOT_ON_ACCOUNT`. When credentials are supplied without a MAC, registration binds the single distinct account device automatically; a multi-device account requires an explicit selection (422 `AMBIENT_MAC_REQUIRED`). A retained MAC takes precedence on updates. Without credentials or a MAC, registration makes no new device claim. An empty account rejects a submitted MAC with 422. Key rotation must also validate any retained MAC when the request omits it. Metadata-only same-owner updates can retain the existing binding without resupplying credentials.

A transaction-scoped advisory lock in namespace 1261 serializes each normalized MAC across wallets, after the existing per-owner lock. The query rejects a MAC held by any other active owner (or a null owner), returning 409 `MAC_TAKEN`. Same-owner re-registration is allowed. An inactive row does not reserve the MAC. Admin override cannot bypass this MAC guard. Lookup/lock failure refuses admission. This protects this registration service; external database writers must use equivalent admission rules. It does not introduce a chain binding or change chain-station-backfill.

The route already checks out one database connection, begins a transaction, and commits only successful registration. Direct callers must honor that contract: autocommit releases advisory locks too soon. Provider verification and elevation lookup finish before locks are acquired. Tests model transaction-held locks and committed visibility; they are local dependency-injected evidence, not a live Postgres concurrency claim.

MAC remains in restricted station metadata for existing integrations. The station-list service returns an explicit projection without MAC/metadata; the anonymous route additionally removes MAC spellings and raw metadata. Registration responses/errors never echo MAC or provider keys. No database migration or deploy was performed.
