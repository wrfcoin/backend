# Daily weather temperature archives

Refs backend#1117. This worker archives the already published daily air-temperature summaries from `weather_temperature_daily_release`. It does not scan raw submissions, create additional releases or include station, wallet or device identifiers. Other weather variables have no reviewed daily release table and are excluded.

Payload `weather-temperature-daily/v1` contains a UTC day and a sorted list of cells with integer tenths (`latE1`, `lonE1`), `minC`, `maxC`, `meanC` and `countBucket`. Values retain the release policy: 0.5°C steps and counts rounded down to tens. Suppressed all-null cells are omitted entirely, so their observation presence is indistinguishable from absent cells. All-suppressed and empty days create no archive or receipt; adding suppressed cells changes neither public bytes nor digest. Days remain ineligible until their two-hour publication grace expires. Coordinate precision never exceeds 0.1°.

Each day's first snapshot receives one IPFS CID, recorded with payload SHA-256, byte count, cell count and archive time in `WRFCOIN_WEATHER_ARCHIVE_DIR/YYYY-MM-DD.json`. Installation is atomic, does not overwrite a concurrent first receipt, and syncs file and directory. Restart reads the existing receipt before querying or uploading. Later cell releases do not revise an archived snapshot; this is a first-publication snapshot, not a complete census. Back up the receipt volume with Kubo data. Losing receipts can permit a new snapshot; retaining receipts while losing Kubo data does not establish retrieval availability.

The separate entrypoint is disabled unless `WRFCOIN_WEATHER_ARCHIVE_ENABLED=true`. It also requires `DATABASE_URL` and `WRFCOIN_WEATHER_ARCHIVE_DIR`; `WRFCOIN_STORAGE_NODE_URL` defaults to `http://storage-node:7001`. The PostgreSQL connection is read-only with a five-second statement timeout. Every hour, the worker considers the latest 14 released days. Older days require an explicit UTC day argument. Empty release sets create no fabricated archive. A daemon failure records no CID and is retried on a later sweep. At most 100,000 cells and 1 MiB are accepted per daily snapshot; larger summaries remain unavailable.

Deployment requires the reviewed IPFS client, migration `0028_weather_archive_day_index`, a rebuilt backend image including `dist/weather_ipfs_archive.cjs`, owner enablement of the disabled storage profile, and a persistent writable receipt volume. The new day/latitude/longitude index supports date enumeration and each ordered daily scan; apply it before enabling the worker. Its ordinary transaction blocks table writes during index construction. The main API startup is unchanged. No release pin or feature schedule is changed. No worker or service is started by this PR; infra supplies the dependent image entry and opt-in worker wiring.
